# قرارداد اپ سین ژین و سایت سین ژین

نسخهٔ ۱ — ۱۴۰۵/۰۹/۰۷. پایه: بند ۲۰ و ۲۱ در `docs/DECISIONS.md`.
اپ و سایت دو پروژهٔ جدا هستند؛ فقط از راه همین قرارداد با هم حرف می‌زنند. هر تغییری در قالب‌ها با بالا بردن `v` انجام می‌شود.

## اصل‌ها
- **منبع حقیقت: اپ.** سایت قیمت، موجودی یا محصول نمی‌سازد و عوض نمی‌کند؛ فقط نمایش می‌دهد.
- **فقط فیلدهای عمومی.** هزینهٔ ساخت، ضریب‌ها، فاکتور کارگاه، تعداد دقیق موجودی و هر چیزی دربارهٔ مشتری‌ها هرگز به سایت نمی‌رسد.
  این را تابع `siteCatalog` در `js/site.js` تضمین می‌کند و `tests/site.test.mjs` آزمایشش می‌کند.
- **قیمت‌ها:** همان قیمت ویترین اپ، فقط بعد از تأیید سروین (اپ قیمت تأییدنشده را بیرون نمی‌دهد مگر محصول هیچ قیمت تأییدشده‌ای نداشته باشد).
- **سایت فقط «درخواست» می‌نویسد** (بخش ۲)، نه چیز دیگر. هر درخواست را سروین در اپ می‌بیند و تأیید می‌کند.
- **مستقل:** اگر سایت به اپ یا سرور دسترسی نداشت، با آخرین کاتالوگ کار می‌کند.

## ۱. کاتالوگ (اپ ← سایت)

### حالا: فایل
اپ ← تنظیمات ← «خروجی کاتالوگ سایت» یک فایل `seenzhin-catalog-YYYY-MM-DD.json` می‌دهد، فقط محصولاتی که
«روی سایت نشان بده» دارند. عکس‌ها داخل همان فایل‌اند.

### بعداً: زنده
همین قالب از یک آدرس فقط‌خواندنی روی میزبان ایرانی (عکس‌ها به‌صورت آدرس جدا، نه data URL). سایت نباید عوض شود جز خواندن `photos[].url` به‌جای `photos[].data`.

### قالب (v1)
```json
{
  "app": "seenzhin",
  "kind": "catalog",
  "v": 1,
  "at": "2026-11-28T09:00:00.000Z",
  "currency": "IRT",
  "items": [
    {
      "id": "lq3k8a2f9x",
      "title": "گوشوارهٔ نمونه",
      "desc": "دو خط برای معرفی، نوشتهٔ سروین",
      "category": "جواهرات",
      "type": "گوشواره",
      "material": "نقره",
      "weight": 8,
      "price": 12000000,
      "availability": "available",
      "photos": [{ "id": "ph1", "data": "data:image/jpeg;base64,..." }]
    }
  ]
}
```

| فیلد | نوع | معنی |
|---|---|---|
| `currency` | `"IRT"` | همهٔ قیمت‌ها **تومان**. |
| `id` | رشته | شناسهٔ ثابت محصول در اپ؛ برای آدرس صفحهٔ محصول و برای درخواست‌ها (`productId`). |
| `title` | رشته | نام محصول (گاهی انگلیسی، مثل Dantel). |
| `desc` | رشته | توضیح کوتاه فروش؛ ممکن است خالی باشد. |
| `category` | رشته | یکی از: جواهرات، تابلوی نقره، تندیس و مجسمه، دست‌سازها. |
| `type` | رشته | زیردسته: انگشتر، گردنبند، گوشواره، سنجاق؛ کوچک، متوسط، بزرگ؛ تندیس، مجسمه؛ ظروف، اشیای دکوری، سایر. |
| `material` | رشته | نقره، طلا، برنز، یا خالی. |
| `weight` | عدد یا `null` | گرم؛ فقط برای فلزی که خود سین ژین می‌دهد (نقره، طلا). |
| `price` | عدد یا `null` | قیمت ویترین به تومان. `null` یعنی هنوز قیمت ندارد → «تماس بگیرید» نشان دهید. |
| `availability` | `"available"` یا `"made-to-order"` | آماده برای فروش، یا فعلاً عددی آماده نیست و سفارشی ساخته می‌شود. تعداد دقیق عمومی نیست. |
| `photos` | آرایه | به ترتیب؛ اولی عکس اصلی. هر عکس JPEG، ضلع بزرگ حداکثر ۱۴۰۰ پیکسل. |

قیمت با قیمت روز نقره تغییر می‌کند (پس از تأیید سروین)؛ سایت قیمت را از کاتالوگ بخواند، هرگز در کد ننویسد.
سیاست فروش: یک قیمت همه‌جا؛ هزینهٔ ارسال جدا.

## ۲. درخواست‌ها (سایت ← اپ) — پیش‌نویس، هنوز ساخته نشده

سایت فقط این را می‌فرستد؛ اپ آن را در صندوق «درخواست‌های سایت» نشان می‌دهد و سروین به مشتری یا سفارش تبدیلش می‌کند.
```json
{
  "kind": "request",
  "v": 1,
  "id": "شناسهٔ تصادفی سایت",
  "type": "custom | question | buy",
  "productId": "برای question و buy؛ برای custom اختیاری (طرح مشابه)",
  "name": "نام",
  "phone": "۰۹…",
  "insta": "اختیاری",
  "message": "متن آزاد",
  "budget": "اختیاری، تومان",
  "createdAt": "ISO 8601"
}
```
- `custom` → در اپ یک «سفارش» در مرحلهٔ «درخواست» (قیمت برآوردی و بیعانه را اپ حساب می‌کند، نه سایت).
- `buy` → در اپ یک پیش‌فاکتور برای همان محصول. سایت پرداخت نمی‌گیرد مگر بعداً تصمیم شود.
- مسیر ارسال (آدرس، کلید فقط‌نوشتنی، ضد اسپم) بعد از انتخاب میزبان ایرانی مشخص می‌شود.

## ۳. سیگنال تقاضا (سایت ← اپ) — پیش‌نویس
شمارش روزانه برای هر `productId`: بازدید صفحه، زدن دکمهٔ سفارش یا سؤال. بدون هیچ اطلاعات شخصی بازدیدکننده.
اپ آن را کنار فروش در «تحلیل» نشان می‌دهد («پربازدید ولی فروش‌نرفته»).
